## 1. High-level overview of the application

Yes, I see the problem.

The **Nvoids Sync + Queue feature is working**, but the **role parser is not clean enough for Nvoids detail pages**.

Your fallback template is fine:

```txt id="kh4uv1"
Subject: Application for {{role}}
```

The issue is that `{{role}}` is sometimes getting filled with dirty Nvoids HTML/job body text instead of a clean job title.

## 4. Core feature issue

For Nvoids, the clean role should come from the **top title row** of the actual Nvoids detail page.

Example from your listing:

```txt id="xlfd2j"
Full Stack Developer (Java, Microservices, Spring Boot, API, ReactJS) -- Charlotte, NC, Islin, NJ & Irving, TX at Charlotte, North Carolina, USA
```

That should become the canonical role/title for draft generation.

But currently, after Nvoids sync, the queue code still calls the generic email parser:

```python id="ngsme9"
parsed = deps.parse_email(request.subject, request.body)
```

Then later the fallback template uses:

```python id="pg1lbg"
str(parsed["role"])
```

for `{{role}}`.  

That generic `parse_email()` was built more for Gmail recruiter emails, not raw Nvoids HTML pages.

The parser already extracts search-page listing rows using BeautifulSoup and gets the link text as `title`. 

But the problem is that the later queue step does **not fully trust that clean Nvoids title**. It re-runs the generic `parse_email()` on the Nvoids body.

That is where the dirty role comes from.

## 6. Important files and folders

### `backend/app/external_feeds/parser.py`

This file parses Nvoids listing rows and detail pages.

Current behavior:

```txt id="u9vgej"
parse_listing_rows()
→ gets title from search page link text

parse_external_post()
→ creates raw_body from title + location + raw detail HTML
→ stores role=title
```

But because `raw_body` includes detail HTML, later parsing can still see things like:

```txt id="bqkgls"
<br />
</tr>
</td>
Job description
Cloudflare email protection
Thanks and Regards
```

That noise can leak into `parsed["role"]`.

### `backend/app/automation/queue_preparation.py`

This is the real place where the bad role enters the draft.

It always does:

```python id="y5hhce"
parsed = deps.parse_email(request.subject, request.body)
```

Then later:

```python id="nyucpl"
str(parsed["role"])
```

goes into the fallback draft.  

So even if `ExternalOpportunity.role` was clean, the queue can overwrite the effective draft role by re-parsing the dirty body.

## 8. Key observations and solution plan

Your solution direction is correct:

**For Nvoids, do not let the generic Gmail parser decide the role from the whole body. Use the first clean title row from the Nvoids detail page.**

Recommended fix plan:

```txt id="9sujt7"
1. Add a Nvoids-specific title extractor in external_feeds/parser.py.
2. From the detail page, read the first meaningful row after "Home".
3. Ignore email rows, URLs, empty rows, Cloudflare text, and contact rows.
4. Use that row as canonical_nvoids_title.
5. Store ExternalOpportunity.role = canonical_nvoids_title.
6. When queueing Nvoids, force parsed["role"] to item.role.
7. Only then build fallback/AI draft.
```

The key rule should be:

```txt id="5jr4fj"
For source = nvoids:
{{role}} must come from ExternalOpportunity.role,
not from parse_email(subject, body).
```

Add a safety cleanup:

```txt id="yiq2os"
If role contains <br, </, <td, <tr, href, data-cfemail, Job description, Thanks and Regards,
reject that parsed role and fall back to the clean Nvoids title.
```

Expected final behavior for Email ID 3531:

```txt id="d66d7x"
Subject: Application for Full Stack Developer (Java, Microservices, Spring Boot, API, ReactJS) -- Charlotte, NC, Islin, NJ & Irving, TX at Charlotte, North Carolina, USA

Dear Recruiter,

I am writing to express my interest in applying for the position Full Stack Developer (Java, Microservices, Spring Boot, API, ReactJS) -- Charlotte, NC, Islin, NJ & Irving, TX at Charlotte, North Carolina, USA.
```

In simple terms:

**The Nvoids parser already has access to the clean listing/title area, but the queue later re-parses the dirty HTML body and corrupts `{{role}}`. Fix the Nvoids path so the clean first-row title is locked as the role and cannot be overwritten by the generic email parser.**
